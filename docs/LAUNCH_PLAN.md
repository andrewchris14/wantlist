## Cost and hosting decision

Cloudflare Free is plausible for a modest personal collection, but **not yet demonstrated reliable for this optimized application**. Before optimization, four routes exceeded its 10-ms CPU limit and a maximum Save consumed about 2.43m reads. Local optimization reduced maximum Save SQL work 98.4%; this is not proof of billed reads or Worker CPU. The successful no-D1 probe proves routing only. One Paid month cannot fix an ongoing Free CPU failure after downgrade.

For the import, Free is feasible but slow: the existing conservative reservation is about **806,001 writes** for the estimated missing records; the existing 60,000/day safety budget needs approximately **14 quota days**. These are bounds/estimates, not billed totals. A separately approved month of Workers Paid could avoid that daily import bottleneck and shorten the import window. Its advertised $5 base is not an unconditional total bill or spending cap: confirm current included D1/Workers allowances, account-wide consumption and a fixed authorized budget before subscribing. Do not activate now. Schedule and verify downgrade; recheck Free D1 per-database size and other limits first. Monthly billing/downgrade timing must be confirmed in the dashboard before promising a single charge.

If this application's essential editing still cannot fit Free, the simplest credible $0 recurring fallback is a static public collection on GitHub Pages, with owner editing in an offline/local tool and deliberate publication of the public projection. Private database/history/backups must stay outside the public repository. That changes the browser-editing/publishing workflow and needs explicit owner acceptance and some implementation; it is not a drop-in replacement for the working backend. No alternative hosted database service is claimed to preserve every feature at $0 without evaluation. Prefer completing the existing Cloudflare route if the targeted acceptance succeeds.
